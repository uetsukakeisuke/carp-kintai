# カープ勤怠

株式会社カープエージェンシーのシフト・打刻・勤怠管理システムです。スマレジ・タイムカードの置き換えとして、まずシフト・打刻・税理士事務所への給与報告を担います。

- **スタッフ**：スマホで打刻（もう一度出勤にも対応）、カレンダーで自分のシフトと出勤を確認、シフト希望の提出、全員のシフトの閲覧、打刻の修正申請
- **店長・管理者**：予定人件費をリアルタイムで見ながらシフト作成・公開、希望の提出状況、勤怠実績と修正申請の承認、スタッフと時給（適用開始日つき・最低賃金チェック）、給与報告フォーム（Excel）の出力、店舗と予算、店舗端末の設定
- **店舗端末**：休憩室のタブレットで、名前を押して4桁のパスワードで打刻

**ログインと打刻**
- スタッフ：ログイン画面で自分の名前を押すだけで入れます（パスワードなし）。
- 打刻：出勤・休憩・退勤を押すたびに、全員共通の打刻コード `1111` を入力します（店舗端末も同じ）。コードは Vercel の環境変数 `PUNCH_CODE` で変えられます。
- 店長・管理者：給与や時給を扱うため、ログインには4桁のパスワードが必要です。初期は `1111`。変更は任意で「その他 → 自分のパスワードを変える」から（打刻コードと同じ 1111 のままだと、スタッフも店長として入れてしまうので変更をおすすめします）。5回続けて間違えると15分ロックし、管理者が `1111` に戻せます。
- シフト希望：「希望の提出状況」で月ごとに受付開始日と締切日を決められます。期間外はスタッフが入力・変更できません。

## 本番環境の用意（初回だけ・約30分）

使うサービス（20名程度なら無料枠で収まる見込み。データ量や利用状況で有料プランが必要になる場合があります）

| 役割 | サービス |
| --- | --- |
| プログラムの置き場 | GitHub（非公開リポジトリ） |
| データベース | Supabase（東京リージョン） |
| アプリの公開 | Vercel |

### 1. データベース（Supabase）

1. https://supabase.com でアカウントを作り「New project」。Region は **Northeast Asia (Tokyo)**、データベースのパスワードは控えておく。
2. プロジェクトの「Connect」→「**Transaction pooler**」の接続文字列をコピーし、`[YOUR-PASSWORD]` を控えたパスワードに置き換える。これが `DATABASE_URL`。
3. パソコンでこのリポジトリを開き、次を実行（Node.js 20 以上が必要）

```bash
npm install
cp .env.example .env.local      # DATABASE_URL を貼り付ける
export $(cat .env.local | xargs)
npm run db:migrate               # テーブルを作る
npm run db:seed                  # 店舗（お酒の水族館・京都工房）と管理者（上塚 佳祐／1111）を作る
```

4. スタッフの登録は、画面の「スタッフ・時給」から1人ずつでも、これまでの給与報告フォームから一括でもできます。

```bash
npm run import:staff -- 2610給与報告フォーム.xlsx 2026-12-01 --dry-run   # 読み取り内容の確認だけ
npm run import:staff -- 2610給与報告フォーム.xlsx 2026-12-01             # 登録する
```

閉店した店舗（motto鯉）の行は取り込みません。交通費は登録後に画面で入力してください。

### 2. アプリの公開（Vercel）

1. https://vercel.com に GitHub アカウントでログインし「Add New → Project」でこのリポジトリを選ぶ。
2. 「Environment Variables」に `DATABASE_URL` を登録し、Region を **Tokyo (hnd1)** にして Deploy。
3. 発行された URL（例 `https://carp-kintai.vercel.app`）を開き、上塚 佳祐／1111 でログインして自分のパスワードに変更する。
4. 必要なら独自ドメイン（例 `kintai.carpagency.net`）を Vercel の「Domains」で設定する。

### 3. 店舗での準備

- 「店舗・端末」で各店舗の1日あたりの人件費予算を入れる。
- 店長にする人は、管理者が「スタッフ・時給」→「編集」→ 権限「店長」にする。
- 休憩室のタブレットで店長がログインし、「店舗・端末」→「この端末を店舗端末にする」。以後そのタブレットは打刻専用になり、名前を押して打刻コードを入れるだけで打刻できる（解除は店長のパスワードで）。
- スタッフには URL を送り、スマホのホーム画面に追加してもらう（アプリのように起動できる）。

## 計算のルール

| 項目 | ルール |
| --- | --- |
| 実働 | 出勤〜退勤の区間をすべて合計し、休憩を引く（間違えて退勤→もう一度出勤しても合計） |
| 日付をまたぐ勤務 | 5:00 より前の打刻で前日がまだ退勤していなければ前日の続き（1:30 → 25:30） |
| 残業 | 1日8時間を超えた実働。給与報告の「残業時間」欄へ |
| 深夜 | 22:00〜翌5:00 の実働（深夜帯の休憩は除く）× 時給 × 25% |
| 予定人件費 | シフトから計算。6時間超で45分、8時間超で60分の休憩を自動で引く |
| 時給 | 適用開始日つきで管理。過去の勤務は当時の時給で計算。最低賃金（京都府）を下回る設定は保存できない |
| 給与報告 | 給与報告フォームの書式・計算式そのままに記入。月の途中で時給が変わった人は時給ごとに行を分ける。退勤のない勤務と当日分は含めない |

最低賃金は `db/migrations/001_init.sql` に京都府の金額（2025/11/21〜1,122円、2026/11/16〜1,180円）を入れています。改定時は `min_wages` に1行追加してください。

## 開発

```bash
npm run db:local            # 開発用のデータベースを起動（別のターミナルで）
export DATABASE_URL=postgres://postgres@127.0.0.1:5433/postgres
npm run db:migrate && npm run db:seed -- --demo   # 架空のスタッフ入り
npm run dev                 # http://localhost:3000
npm test                    # 計算ロジックのテスト
npm run typecheck
```

## セキュリティ

- 店長・管理者のパスワードは bcrypt でハッシュ化して保存。ログイン情報は HttpOnly の Cookie。
- スタッフは名前だけでログインできるため、他人の名前を押せばその人として打刻・閲覧できます。スタッフ画面に時給や給与は出しませんが、URL は社外に広めないでください。
- データベースは行レベルセキュリティを有効にし、アプリのサーバーからだけ接続（Supabase の公開APIからは読めない）。
- 権限の確認はすべてサーバー側で行う。スタッフ画面・ログイン画面には時給や給与を出さない。
- 主な操作（シフト編集・公開、時給変更、修正承認、パスワードのリセット、給与報告の出力）は `audit_log` に記録。
- ログイン画面には在籍スタッフの名前が表示されます（名前を選ぶ方式のため）。URL は社外に広めないでください。

## 給与明細（アクトヴィジョンのメールから）

- アクトヴィジョンの「給与明細のご送付」メールに付いている「給与支給明細書」PDFを読み取り、スタッフごとの明細として保存します（支給控除一覧表は取り込みません）。
- 自動取り込み：管理画面「給与明細」に表示される Google Apps Script を info@carpagency.net の script.google.com に貼り、`setup` を1回実行。以後1時間ごとに Gmail を確認し、`/api/payslips/import` に送ります（合言葉つき。取り込んだメールには「勤怠アプリ取込済み」ラベル）。
- 手動：同じ画面からPDFを選んで取り込むこともできます。同じ月は上書き。
- 照合：明細書の氏名（空白・凛/凜・ケ/ヶの違いは無視）→ 次回からは明細書の従業員コードで自動照合。結びつかない人は画面で選ぶか「対象外」に。
- スタッフは「明細」から本人の4桁の暗証番号（初回に決める・1111等は不可）で開きます。10分で自動で閉じ、5回間違えると15分ロック。管理者は「給与明細」画面で全員の暗証番号を確認でき（本人にもそう表示）、「スタッフ・時給 → 編集」で消せます。
